# 六地气温爬虫

抓取海南、韶关、梅州、茂名、广州、深圳六个城市的**逐小时气温与体感温度**，把历史实测数据和未来 7 天预报合并成两份可直接查阅的 Excel 表格。数据来自 [Open-Meteo](https://open-meteo.com/) 免费接口，**无需注册、无需 API Key**。

**怎么用：** 装好依赖后执行 `python -m sixcity_temp`，程序会在当前目录生成两个 Excel 文件。

**注意事项：** 必须联网；用 WPS / Excel 打开着生成的表格时需要先关闭文件，否则写不进去。

---

## 一、项目解决什么问题

查天气网站只能看到「今天最高 28℃、最低 21℃」这样的日均值，做不了下面这些事：

| 日常需求 | 手工做时的麻烦 | 本项目的做法 |
|----------|----------------|--------------|
| 看某天某个时刻到底多少度 | 天气网站不提供逐小时数据，得反复翻页面 | 每天 24 个小时逐时值，一行就是一天 |
| 对比多个城市的气温 | 六个城市六个网站，来回切换、手工抄 | 一次运行，六个城市各一个工作表 |
| 同时看气温和体感温度 | 体感温度只在部分 App 里有，且不能导出 | 单独一份体感温度表，含最高 / 最低 / 平均体感 |
| 存档历史数据做趋势对比 | 截图、复制粘贴，格式还各不相同 | 历史 + 预报合并成一张标准表格 |
| 把数据给自己或同事 | 格式乱、缺列 | 输出样式统一的 Excel，冻结窗格、当天行高亮 |

一句话：**把分散在各个天气网站上的六地逐小时气温与体感温度，变成可以存档、可以对比、可以再加工的 Excel 表格。**

## 二、主要功能

- **一次运行产出两份表格**：`六地气温(历史+预报).xlsx` 与 `六地体感温度(历史+预报).xlsx`，每个城市一个工作表。
- **数据覆盖完整历史 + 未来**：默认从 `2025-01-01` 起一直排到今天（含）往后第 6 天，历史实测与未来预报拼成一条连续时间轴，重叠部分以实测为准。
- **自动区分「实际」与「预测」**：当天及之前标记 `实际`，之后标记 `预测`，一眼看清哪些是已经发生的、哪些是还没验证的。
- **表格自带样式**：冻结窗格、表头加粗、居中边框、列宽适配、当天行橙色高亮、打开后光标自动定位到当天那一行。
- **容错与补救**：请求失败自动重试；按错误类型分类补救 —— 超时放宽到 60 秒、限流（429）等待 60 秒、服务端故障（5xx）等待 30 秒、连接失败等待 10 秒；历史接口若拒绝最新日期会自动把截止日期回退 5 天。
- **单个城市失败不影响其余城市**：失败城市跳过并在日志中说明，其余城市照常导出，退出码标记为「部分失败」。
- **城市列表可自定义**：内置六城，也可用 JSON 文件换成任意城市（如「汕头」），还能按名字筛选只抓其中几个。
- **跨平台**：纯 Python 实现，Windows / Linux / macOS 均可运行；Windows 下另附一键运行的 `运行.bat`。

## 四、使用方法

### 最简用法

```bash
sixcity-temp
```

或在当前目录执行：

```bash
python -m sixcity_temp
```

在**当前目录**生成两个文件：

- `六地气温(历史+预报).xlsx`
- `六地体感温度(历史+预报).xlsx`

### 常用示例

```bash
# 指定输出目录（不存在会自动创建）
sixcity-temp --output-dir ./输出

# 只抓两个城市，加快速度
sixcity-temp --only-city 广州 --only-city 深圳

# 改历史起点，缩小数据量、加快速度
sixcity-temp --history-start 2026-01-01

# 使用自定义城市列表
sixcity-temp --cities examples/cities.example.json

# 不做样式美化，只写原始数据
sixcity-temp --no-style

# 排查问题时打开详细日志
sixcity-temp --log-level DEBUG
```

### 命令行参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--output-dir` | 当前目录 | Excel 输出目录，不存在会自动创建 |
| `--history-start` | `2025-01-01` | 历史数据起始日期，格式 `YYYY-MM-DD` |
| `--cities` | 内置六城 | 自定义城市 JSON 文件 |
| `--only-city` | 全部 | 只抓指定城市，可重复传入；与 `--cities` 配合使用 |
| `--timeout` | `30` | 单次请求超时秒数（超时补救时自动放宽到 60） |
| `--retries` | `3` | 单个城市的最大尝试次数 |
| `--no-style` | 关闭 | 不美化 Excel，只写原始数据 |
| `--log-level` | `INFO` | 日志级别：`DEBUG` / `INFO` / `WARNING` / `ERROR` |

### 退出码

| 退出码 | 含义 |
|--------|------|
| `0` | 全部城市成功 |
| `1` | 部分城市失败（其余城市已正常导出） |
| `2` | 参数或配置文件有误（日期格式错、城市名不匹配、JSON 损坏） |
| `3` | Excel 导出失败，通常是文件被 WPS / Excel 占用 |

## 隐私与发布

本项目只处理气象数据，**不采集、不写入任何可追溯到运行者的信息**：

- Excel 文档属性中的作者字段固定为 `sixcity-temperature-crawler`，不含用户名或机器名。
- 程序不读取设备标识、网络地址、账号等任何本机信息，只向 `api.open-meteo.com` 与 `archive-api.open-meteo.com` 请求气象数据。
- 产出文件里只有日期、天气与气温数值。

发布前建议跑一次自检：

```bash
python tools/预发布自检.py
```

它会检查密钥、个人信息、本机绝对路径、缓存与运行产物、Excel 文档属性五类风险，有问题以退出码 1 结束。

> 两个容易忽略的坑：
>
> 1. `__pycache__/` 里的 `.pyc` 会内嵌源码的**绝对路径**。用 zip 打包分发前务必先删掉该目录。
> 2. 用 WPS / Excel 打开生成的表格后**另存**，该软件会把你的 Windows 账户名写进文件属性。对外分享前请检查「文件 → 信息 → 属性」。

## 常见问题

**Q：提示文件被占用？**
生成的 Excel 正被 WPS / Excel 打开时无法写入。关闭文件后重跑即可，程序会给出明确提示并以退出码 `3` 结束。

**Q：某个城市抓取失败怎么办？**
先看 `--log-level DEBUG` 的日志。程序会重试 3 次并按错误类型补救一次，仍失败则跳过该城市，其余城市照常导出，退出码为 `1`。

**Q：需要注册或密钥吗？**
不需要。Open-Meteo 的历史与预报接口公开可用。

**Q：数据准吗？**
`实际` 部分来自 Open-Meteo 的实测再分析数据，`预测` 部分是模型预报。程序本身不做二次校正。
